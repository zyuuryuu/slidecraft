# ADR-0037: MCP サーフェス再設計の原理 — 用途の主従とループ温度で整列する

- Status: Accepted（2026-10-06）
- Date: 2026-10-06

## Context

MCP のツール面は 18（[ADR-0008](0008-mcp-tool-surface-audit.md)・6 月）から 38（2026-09 時点）へ 3 ヶ月で
倍増した。各追加は局所的に正当（[ADR-0015](0015-mcp-surface-brushup.md) の構造操作・
[ADR-0034](0034-convenience-slide-generation.md)/[0035](0035-mcp-bulk-data-exchange.md)/
[0036](0036-scope-template-discovery.md)）だが、**用途レベルの設計単位が無いまま堆積**し、
説明文＋スキーマで毎セッション約 5–6k トークンの固定費になっている。診断の入口が 3 系統・ガイドが 4 ツール・
read がツール＋リソースの二重面という読解コストも積み上がった。診断と方向性の全体は
[docs/design/mcp-value-realign.md](../design/mcp-value-realign.md)（議論スナップショット・2026-09-28）にあり、
本 ADR はそこで**ユーザと合意した決定部分**を永続化する（合意: 2026-09-28 チャット＋2026-10-06 の v0.5 GO）。

製品の北極星は「**手元の AI に指示を出すと、シームレスに出来上がっていくスライドが見える**」
（ライブ共著ループ・[ADR-0009](0009-collab-host.md)/[0033](0033-mcp-single-control-plane.md) の延長）。
U1 のホットループでは 1 指示あたりの往復・トークンが**人が画面の前で待つ体感レイテンシそのもの**であり、
サーフェスの肥大は品質問題である。

## Decision

### D1. 用途の主従（これがサーフェス設計の第一軸）

| # | 用途 | 位置づけ |
| --- | --- | --- |
| U1 | ライブ共著（GUI＋隣の AI が MCP 編集） | **主（製品の核）** |
| U2 | headless 著作（stdio 単独） | 従（U1 の劣化モード・入口として維持） |
| U3 | テンプレ工務の AI フル委譲 | **維持**（削減対象にしない・ユーザ確認済み） |
| — | CI/バッチ生成 | 未決（決めるときに追記） |

### D2. ループ温度の原理（CRUD 分類ではなくこれで束ねる）

- **コールド（セッション 1 回）**: 調達・契約（ガイド 4 ツール・capabilities・list_templates）は
  **1 発の bootstrap に統合してよい**（太くても 1 回きり）。旧ツールは alias として当面維持する。
- **ホット（毎指示）**: 著作・レバー・診断・read は**最小・直交・低トークンを死守**。1 往復の削減が体感に直結。
- **出口（稀）**: export/save/validate は現状維持。
- **人間側ツール**（undo/redo・doc 切替・register_templates）: 削除しない。ただし**プロファイル別登録**で
  solo（stdio 単独）セッションには collab 専用ツールを見せない（`register_templates` の host 限定登録が既存の前例）。

### D3. 拡張は「まず md-DSL 側で」

md-DSL（マーカー・フィールド行）は**安い拡張面**（ツール面を増やさない。#396–#404 の語彙輸入が実例）、
ツール面は**高い拡張面**（毎セッションの固定費）。機能追加はまず md-DSL で表現できないかを問い、
ツール追加はホットループの往復を減らす場合に限る。

### D4. 削除は最後・証拠つき

段階は**追加 → alias → 縮退**。縮退（削除）は実セッションの呼び出し頻度・実効性の監査（証拠）が
揃ってからのみ行う。[ADR-0008](0008-mcp-tool-surface-audit.md) の互換性フロア（読み取りツール削除禁止・
do-NOT-undo ペア統合禁止）は**存続**する — bootstrap 統合（alias 維持）とプロファイル別**登録**
（ツールは存在し続け、見せる相手を選ぶだけ）はフロアに抵触しない。フロア自体の supersede は、
証拠が削除を正当化した時点で個別 ADR として判断する。

### D5. 合否指標

1. **time-to-first-visual**（指示から最初の視覚変化まで）
2. **1 指示あたりの往復数・トークン**（コールド分離後のホットループで）
3. **変化の増分性**（deck 丸ごと再生成に落ちる操作をゼロへ近づける）

## Consequences

- 実装は子タスクに分割する（#406 がハブ）: 証拠集め（敵対的監査）→ コールド bootstrap 統合（alias 維持）→
  プロファイル別登録 → 指標の計測手段。v0.5.0 のスコープは bootstrap 統合とプロファイル別登録まで。
- 以後のツール追加 PR は、本 ADR の温度分類（コールド/ホット/出口/人間側）と D3 への適合を PR 本文で
  宣言すること（レビュー統括が照合する）。
- U2/U3 の既存機能は縮退しない。alias 移行中は新旧の入出力互換を保つ。
